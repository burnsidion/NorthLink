# OWL-58 checkpoint 1: safe purchase changes

Prepared November 14, 2026 (America/Denver). Local implementation only.
No hosted migrations, commits, pushes, PRs, or Linear edits performed.

## Agreed behavior

Owners keep seeing which gifts are purchased. Only the buyer may undo a purchase.
Buyer identity will become private in checkpoint 2, with the future Christmas
reveal implemented as a separate, authorized read path. This checkpoint does
not remove existing buyer records, migrate old purchases, or implement reveal.

## Changes

- A private, tightly scoped function locks one item, checks the signed-in
  caller's current ownership/share access, and claims or cancels it.
- The public API wrapper accepts only item ID and desired purchased status.
  The backend assigns buyer/time; the response contains only purchased status/time.
- One competing shopper wins. Others receive a conflict without overwriting the
  winner. Retrying the winner's claim keeps the original purchase timestamp.
- Cancellation requires the recorded buyer and current list access. Cancellation
  retries on an already-unpurchased accessible item succeed without changing data.
- Auth accounts missing a profile receive a useful error instead of a foreign-key
  failure. Existing owners' self-purchases remain supported.
- Direct INSERT/UPDATE purchase fields are blocked, including forged purchases
  on new items. Owners can still create items and edit normal gift fields;
  shoppers cannot. Rewriting item IDs/list IDs/creation times is not permitted.
- Both the active helper and the older server action use the new purchase API.
  The server action's existing session wiring is not otherwise refactored.
- The checkbox saves immediately. It disables duplicate submissions, waits for a
  confirmed response before checking/celebrating, releases controls after failure,
  and suppresses its later animations after unmount. Conflicts/errors refresh the
  item list instead of restoring an old snapshot over newer changes.

## Explicit limits

**Buyer identity remains readable from items until checkpoint 2.** Do not mark
OWL-58 as complete based on this slice. Moving identity to private storage also
requires updating My Purchases and verifying realtime/REST/GraphQL read paths.

Existing owner deletion of items/lists is unchanged; deletion removes the item
and its purchase information. Decide retention for deleted gifts before building
the Christmas reveal. This change is not a purchase audit-history feature;
an intentional cancellation clears the active buyer/time as before.

Loss of sharing still removes access, including purchase cancellation. Existing
records whose buyer lost sharing are preserved, without granting new access.
The update policy and grants are tighter, but the legacy claims table is untouched.

## Tests

```sh
bash supabase/tests/run-owl-58.sh
node --test supabase/tests/purchase-client.test.cjs
npx tsc --noEmit --incremental false
npm run build
```

The runner uses the existing structure fixture and fake records in a disposable,
network-isolated PostgreSQL 17 container. No ports, persistent volume, .env
credentials, or hosted connections. The container is removed on exit.

It verifies prior access/invitation behavior before tightening purchases, applies
and reapplies the new migration, checks caller/owner/shopper/outsider permissions,
missing profiles, invalid inputs, forged fields, cancellation, retry timestamps,
unsharing, and owner item creation/editing. Separate concurrent sessions must
record exactly one winner and one conflict, with the recorded buyer matching the
winner. Eight client tests exercise the actual helper and checkbox click handler
with mocked transport/hooks: immediate submission, duplicate clicks, malformed
responses, conflicts, network failures, retry, and unmount behavior.

These are real SQL permission tests plus focused client behavior tests, not a
full browser/Auth/PostgREST integration test. A deployed smoke test remains needed.

Validation passed: SQL suite including migration reapplication and independent
concurrent sessions; all eight client tests; TypeScript; production build;
focused ESLint on items-api, the checkbox, and the server action. The modified
list page retains existing lint findings (seven errors/nine warnings, previously
eight errors/nine warnings). Existing build deprecation warnings remain.
